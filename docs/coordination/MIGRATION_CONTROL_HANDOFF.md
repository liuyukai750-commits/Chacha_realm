## 1. 总控任务

当前工作不是重做猹猹街，也不是借迁移改变产品。目标是：

1. 把现有 Vercel + Supabase 耦合收敛成可替换边界；
2. 为腾讯云上海应用与标准 PostgreSQL 迁移做好可演练、可回滚的准备；
3. 迁移整合后，`codex/preview` 已有的用户功能、接口语义、数据和视觉体验全部保持不变；
4. 在不改变业务语义的前提下，减少中国大陆用户首次打开、列表展开、瓜详情和评论读取的等待；
5. 所有真实数据库、腾讯云、DNS、SSL、正式域名、commit、push 和部署操作继续受用户明确授权约束。

最高裁决原则：**功能零回退，数据不丢失，隐私权限不降级；性能优化必须有测量依据，不能用删功能或放宽安全换速度。**

## 3. 不得回退的用户功能

### 3.1 身份与账号

- 新用户使用猹号 + 密码创建账号，选择六种原创动物头像并设置最多 12 个可见字符的昵称。
- 中文输入法组合阶段不能被字符上限截断。
- 永久公开猹号、昵称、动物头像与个人瓜田绑定；刷新、跨设备重新登录后数据仍在。
- 恢复码、退出、注销和旧账号原地补密码路径保持可用；UUID、猹号、瓜田、瓜籽、帖子、评论、点赞和蹲瓜关系不得改变。
- “猹猹国王”是唯一主理人身份，仅显示克制的“主理人”标识；公开身份与后台运营权限分离。
- 前台不公开手机号、Supabase UUID、精确位置、钱包或认证事件。

### 3.2 五城、定位与埋瓜

- 长沙、北京、上海、广州、深圳共享同一业务规则，所有城市相关改动必须走五城矩阵，不能只验长沙。
- 城市瓜区、普通附近生活圈、公共地点三种场景语义保持独立；五城昼夜地标视觉保持现状。
- 手动切城只影响浏览，不能伪造用户所在城市。
- `public_spot`：用户必须真实定位在五个开放城市之一，只能选择当前所在城市的公共地点；不要求人在地点附近。成熟后该城市全域可见、可吃、可点赞和蹲后续；只有距离该公共地点 1 公里内可以文字评论。
- `nearby_area`：发布时保存服务端私有固定锚点；成熟后只有该锚点 1 公里内的用户可发现、打开、读评论和评论；不得混入城市瓜区或跟随作者移动。
- 五城外或未定位用户可浏览城市公区瓜，但不能埋瓜或发表评论；不得把手动城市选择当定位。
- 精确坐标不进入公开响应、普通日志或轨迹，只允许存在于默认拒绝访问的私有位置锚点。
- 社区故事瓜统一 3 分钟成熟；个人瓜田的游戏瓜仍为 12 小时成熟。

### 3.3 吃瓜、评论与互动

- 成熟瓜可直接打开；远程公区用户可读正文和公开评论、完成有效吃瓜、点赞、蹲后续。
- 评论保持单层，无评论回复、私信、好友、用户关注或 @。
- 附近瓜只对锚点 1 公里内用户开放；公区文字评论只对公共地点 1 公里内、持短时 presence token 的用户开放。
- 互动只保留“点赞”和“蹲后续”；再次点击取消，数字即时乐观更新，失败恢复原值并明确提示。
- 瓜详情以标题、作者动物头像 + 昵称、正文和评论为主体；不得恢复“扒开草丛”、大图框、布帘或竖条装饰。
- 从瓜篮、蹲瓜架和“我埋下的瓜”点击条目应立即打开详情壳层，不能因触摸滑动误触发“不看了”或删除。

### 3.4 瓜篮、蹲瓜架与我的瓜

- 瓜篮是待吃发现流，按时间从新到旧；显示动物头像、昵称、带 `[]` 的标题和时间戳。
- 有效吃完后从个人瓜篮消失；左滑“不看了”只隐藏个人条目，不删除原帖。
- 蹲瓜架独立保留已蹲的瓜，即使已经吃完或从瓜篮隐藏，直到用户主动取消蹲瓜。
- 蹲瓜架显示动物头像、昵称、带 `[]` 的标题和时间戳；站内成熟提醒通过页面打开、重新聚焦或轮询刷新，不承诺系统推送。
- “我埋下的瓜”只显示动物头像、带 `[]` 的标题、时间戳和状态；点击可查看自己正文与公开评论，删除为瓜主软删除。
- 城市瓜篮、附近瓜篮、个人瓜篮和蹲瓜架必须使用一致的数据排序与交互语义。

### 3.5 瓜籽与瓜田闭环

- 每天前五次有效吃完别人的瓜各得 1 颗小瓜籽，第五颗自动换成 1 颗真瓜籽；第六次不再发籽。
- 每日第一颗通过安全检查的原创瓜奖励 1 颗真瓜籽；两个埋瓜入口必须走同一发布和奖励逻辑。
- 三片土地、每片三株、总容量九株；播种消费真瓜籽，个人游戏瓜 12 小时成熟，九瓜全熟后一键收获并增加 9 XP。
- 真瓜籽属于服务端钱包，不得因关闭成功面板、刷新页面、稍后再种或从另一个入口进入而消失。
- 不引入阳光、水、枯萎、偷瓜、任务、商城或多币种。

### 3.6 内容安全、后台与氛围

- 全程公开昵称与动物身份，不允许真实姓名、联系方式、具体门牌、人肉、造谣、色情骚扰、违法引流；举报和封禁必须继续由服务端执行。
- 主理人后台 `/admin` 只读，统计注册、活跃、内容、互动、瓜田经济、五城和治理；不得返回正文、手机号、UUID 或精确位置，也不得扩展成直接删帖/封号后台。
- 背景音乐保持用户确认的极简偷感蓝调循环；按钮靠近顶部城市控件，用户可关闭。浏览器禁止有声自动播放时必须真实降级，不能伪装已播放。
- 375px、430px 为主验收视口，同时覆盖 iOS Safari、Android Chrome、鸿蒙浏览器的能力差异；触控目标、对比度、安全区、键盘和减少动态继续合格。

## 4. 允许修改与禁止扩张

本轮只允许为迁移和性能建立这些边界：

1. `SessionService / SessionStore`：隔离 GoTrue 与本地 opaque session；
2. `DataTransport`：隔离 PostgREST 与标准 PostgreSQL 驱动；
3. 数据库 actor/security context：逐步替代 `auth.uid()/auth.jwt()`，保留或加强现有 RLS/权限语义；
4. 腾讯云 standalone、Nginx、systemd、HTTPS、迁移演练和回滚资产；
5. 不改变 DTO 和用户语义的缓存、请求合并、并行读取、预取和连接复用。

不得借机重写：

- 前端设计系统、页面信息架构、游戏规则和地理规则；
- API 路径和客户端 DTO；
- `island-repository.ts` 的业务编排，除非接口适配不可避免且总控批准；
- 用户 UUID、猹号、钱包、XP、内容、评论、点赞、蹲瓜和位置隐私语义；
- 不得简单关闭 RLS、跳过验证、扩大 mock、删除断言或降低门禁来让迁移“通过”。

## 5. 性能目标与测量方式

优先优化用户真实感知的四段：

1. 首次打开首页；
2. 展开城市/附近瓜篮和蹲瓜架；
3. 点击瓜后显示详情壳层与正文；
4. 评论列表读取与提交后的即时反馈。

要求：

- 先记录当前 Preview 基线，再比较腾讯云应用 + 现有 Supabase、腾讯云应用 + 同区域 PostgreSQL 两阶段结果；
- 分开记录前端渲染、Next API、数据库查询和跨区域网络耗时，不凭感觉归因；
- 详情壳层继续即时打开，正文与评论允许分段加载，但已有内容不能被 loading 覆盖或闪空；
- 相同页面请求应复用会话、连接和短期缓存；写入后做精确失效，不能用长缓存显示旧评论、旧点赞或旧钱包；
- 迁移前后至少比较 p50/p95，且真机网络验证不得被 localhost、局域网或 mock 代替。

## 11. 腾讯云 PostgreSQL 采购提醒

如果最终目标包含“数据库与账号系统脱离 Supabase”，正式切换前需要一个可承载标准 PostgreSQL 的目标数据库。当前不要立即购买，由总控在以下条件全部满足后提醒用户采购：

1. SessionService、DataTransport 和数据库 actor/security context 已在本地完成并保持 Supabase 默认 adapter 可运行；
2. 已统计当前库容量、连接峰值、写入量、备份保留、预期用户量和预算；
3. 已完成标准 PostgreSQL 隔离演练，并确认扩展、函数、索引、RLS/权限与迁移脚本兼容；
4. 已确定应用服务器与数据库的同地域内网方案、回滚方案和测试窗口；
5. 用户明确批准真实云资源采购。

推荐生产目标是**腾讯云云数据库 PostgreSQL（上海地域，托管高可用）**，不选择“轻量数据库服务”，因为腾讯云当前轻量数据库只支持 MySQL 5.7/8.0。现有上海轻量应用服务器与腾讯云 PostgreSQL 默认不直接内网互通，需要评估并配置云联网/VPC 关联；采购前必须确认网段、内网路由和可能费用。

低成本临时演练可以在隔离环境自建 PostgreSQL，但不应把应用与唯一生产数据库长期塞在现有 2 核 2GB 轻量服务器中：这会共享 CPU、内存、磁盘和故障域，且备份、PITR、监控与故障恢复均需自行承担。

总控给用户的采购提醒必须包含：建议产品、地域、规格依据、月费/备份/网络成本、是否支持按量试用、内网连通步骤，以及“不购买会阻塞哪一步”。在这些信息没有核实前，不要求用户下单。
